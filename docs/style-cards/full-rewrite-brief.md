# 全站文风改写执行说明

## 必读

- `docs/style-cards/xiaoke-wiki-风格卡.md`
- `docs/style-cards/xiaoke-wiki-结构.md`
- `docs/style-cards/rewrite-plan.md`

本次按小可 Wiki 文风改写，不重新讨论风格，不改用 Vue 文风。

## 目标

只改叙述文字，让每一页符合小可 Wiki 的教程式说明文风。技术事实、结构信息与可复制内容必须保持不变。

改写后必须逐句复读一遍，检查句子衔接、语序、指代和病句。最后再做一次去 AI 味检查，重点清理空话、套话和口号式表达。

## 硬约束

1. 不修改 front matter、H1、站内链接、图片、图注。
2. 不修改代码块、行内代码、命令、路径、URL、版本号、数字、默认值、参数名、配置键。
3. 不修改 `CommandUsage`、`ChatExample`、`NoticeBox`、`ModuleConfig`、`ModuleData` 等组件的标签、属性、插槽和示例内容。
4. 不修改表格的行列、表头和数据，只允许改表格前后的说明文字。
5. 不新增未核实的行为、参数、默认值、平台限制或失败条件。查不到源码依据时保留原意，不要自行添加内容。
6. 不删除页面现有的技术内容。可以拆段、补总述句、调整叙述顺序，但不要为了“更简洁”丢掉信息。
7. 保留现有标题层级和标题文字。只有明显是问句或空泛标题时才改，且不得改动可能被站内链接引用的标题。
8. 模块使用页保持“用途 → 用法 → 结果 → 限制”的读法，不写成开发教程；开发页保持“介绍 → 结构 → 最小实例 → 扩展”的读法，不写成命令手册；参考页保留签名、参数表和返回值说明，只改导语与连接句。
9. 中文正文使用中文引号“”。代码、命令、URL、英文标识符保持原样。
10. 中文正文不用分号。长句拆成短句，一段 1–3 句。
11. 读者称“你”，机器人称“机器人”，不用“我们”。不用感叹号、比喻、拟人。
12. 不写“读完后，你可以……”“这一页按……展开”“本文按……顺序展开”这类介绍写作意图的句子。
13. 不 commit，不 stage，不改本批次之外的文件。

## 用词

按风格卡的「用词」一节处理。能用具体动作说清，就不用抽象名词。英文缩写、字段名和命令名只在需要精确指代时保留，第一次出现时用一句中文说明它指什么。代码中的原函数名、字段名、命令名保持原样。

## 页面类型

- 适配器页：说明支持范围、配置、消息收发与限制。能力表保留三态，不把“不支持”改成模糊说法。
- 核心指南：先说明这页解决什么问题，再按主题分节。参考型页面保留表格与签名。
- 内置模块页：单命令模块按“用途 → 用法 → 结果 → 限制”；多命令模块按命令拆 H2；Hook 页按“作用 → 触发入口 → 行为 → 配置 → 关联”组织。
- 模块使用页：不要泄露开发细节；技术限制只放在已有的“安装与开发”链接或说明里。
- 模块开发页：保留可运行代码与接口说明；教程步骤按实际执行顺序。
- 索引页：一句说明本页收录什么，保留链接与原有顺序。

## 已改过的页面

`architecture.md`、`module-development.md`、`coin/index.md`、`coin/development.md` 已经在工作区改过。不要回到 HEAD 重写，也不要撤销已有内容。只在当前文本上做同风格的细修，保留已确认的结构与事实。

## 每页流程

1. 读完整页，标出不可改的代码块、表格、组件和链接。
2. 从当前工作区文本出发，改叙述文字。
3. 逐句复读，修掉不自然的中文。
4. 做去 AI 味检查，只改命中的空话和套话。
5. 运行 `git diff --check`。
6. 用 `rg -n '「|」|；' <本批文件>` 检查正文引号和分号。代码块中的分号不算。
7. 人工复读，检查是否还有生硬直译、内部简称或口号式表达。不要用批量替换脚本。
8. 不运行全量构建，构建由主代理统一执行。

## 返回格式

- 已改文件数与页面数。
- 每页一句话说明改了什么。
- 未能处理的页面及原因。
- `git diff --check`、引号/分号、禁用词检查结果。
- 明确说明未 commit。
