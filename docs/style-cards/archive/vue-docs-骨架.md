# 文档站骨架（Vue 指南文风）

这是一份页面骨架，不是某一篇文档的目录。改写时按页面类型选骨架，章节标题可随内容调整，但顺序应保持“先说明是什么，再给最小用法，再讲细节和边界”。

## 通用开场

- 开头 1–2 段：先回答「这是什么」和「它解决什么问题」。
- 不在开头罗列全部参数，也不写「本文介绍……」「接下来我们将……」。
- 需要前置知识时，用一行引用或 `<NoticeBox type="tip">` 说明。

## 类型 A：模块使用页

适用于 `packages/modules/*/doc/index.md`、`packages/akari-bot-core/akaribot/modules/core/doc/*.md`。

```text
# 模块名

一句话说明用途。

## 基本用法
最小可用命令 / 入口，紧跟一个结果说明。

## 参数
只列用户需要填写的参数；没有参数时省略本节。

## 结果
说明机器人会发什么、成功与失败如何区分。

## 示例
保留 ChatExample；示例前后各一句上下文。

## 注意事项
权限、平台限制、边界值、容易误解的行为。
```

单命令模块可以合并「参数」与「结果」；多命令模块按命令拆 `###`，但每个命令仍保持“用法 → 结果 → 边界”的顺序。

## 类型 B：模块开发页

适用于 `development.md`。

```text
# 模块名：安装与开发

一句话说明这个页面面向谁、读完能做什么。

## 安装
安装命令 + 启用方式。

## 配置
配置表 / 字段表 + 一段取值说明。

## 权限与平台能力
模块级限制；没有限制就明确写“无平台限制”。

## 数据表
ModuleData 组件或表结构。

## 依赖与外部服务
内部依赖、网络请求、外部 API。
```

不要把字段表改写成散文；表格前后只补“怎么读这张表”的一句话。

## 类型 C：概念 / 开发指南

适用于 `architecture.md`、`module-development.md`、`message-api.md` 等。

```text
# 标题

定义或问题陈述。

## 它解决什么问题
用一段话说明动机；必要时给一个反例。

## 先看一个例子
最小代码 / 命令，紧跟结果解释。

## 它是怎么工作的
分 2–4 个小节；每节只讲一个机制。

## 边界与常见错误
限制、失败模式、容易踩的坑。

## 接下来
链接到下一篇相关文档。
```

机制复杂时用 `###` 拆开，不把所有内容塞进一个长节。

## 类型 D：适配器页

适用于 `packages/adapters/*/doc/index.md`。

```text
# 平台适配器

它连接什么平台、以什么身份运行。

## 安装
安装命令 + 启动条件。

## 配置
配置表、密钥表、最小配置示例。

## 平台能力
能力表；支持/不支持要写清楚。

## 限制
平台侧限制、权限、消息类型差异。
```

## 类型 E：参考 / 配置 / API 页

适用于 `commands.md`、`config.md`、`message-api.md` 等。

```text
# 标题

一段话说明覆盖范围。

## 快速索引（可选）
表格或链接。

## 字段 / 参数
表格：名称、类型、默认值、说明。

## 示例
最小示例 + 预期结果。

## 边界
错误码、限制、兼容性。
```

参考页不强行写成教程；表格和代码块是主体，段落只负责解释“怎么读”和“什么时候用”。

## 类型 F：FAQ

```text
# 常见问题

## 问题原文？
第一句直接回答。第二段再解释原因或给链接。
```

问题用用户会问的原话，不用「关于……的说明」。

## 类型 G：索引 / 落地页

```text
# 标题

这个入口包含什么、适合谁。

## 从这里开始
3–5 个最常用入口。

## 全部页面（可选）
按主题分组的链接表。
```

索引页不展开细节，只负责指路。

## 段落节奏

- 一个段落只讲一个点，通常 1–3 句。
- 长段落优先拆成「结论句 + 解释句 + 例子」。
- 连续列表不超过 7 项；超过时分组或改成表格。
- 每 2–3 个段落至少出现一个具体例子、命令或链接，避免纯抽象说明。
