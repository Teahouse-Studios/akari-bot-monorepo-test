# 文档站风格卡（Vue 指南文风）

样本：Vue 3 中文文档的「简介」「单文件组件」「Props」「常见问题」四页。只取文风与组织方式，不复制 Vue 的内容、版本号或示例。

## 一、语气与人称

- 面向读者说话，用「你」；描述机器人行为用「机器人」，不用「我」。
- 解释设计取舍时可以用「机器人会……」，避免频繁用「我们」；确需表达维护者立场时再用「我们」。
- 不写「笔者」「本文」「综上所述」「值得注意的是」。
- 不居高临下，也不刻意卖萌；可以有一点点口语过渡，如「先看一个例子」「如果你遇到这种情况」「这时」，但一段最多一处。
- 陈述事实，不写营销式判断：不写「强大」「优雅」「一站式」「显著提升」「无缝」。

## 二、句子与段落

- 一个句子只表达一个判断；长定语拆成短句。
- 一段通常 1–3 句；超过 4 句时拆段。
- 先给结论或定义，再解释原因，最后给例子。
- 多用主动语态：「机器人会发送……」，不写「消息会被机器人发送……」。
- 避免「通过……的方式」「对于……而言」「在……的情况下」连续堆叠；能直说就直说。
- 不为了凑字数加过渡句；删掉后不损失信息的句子一律删。
- 一段最多一个分号。连续用分号串联条件、动作、结果时，拆成短句或列表。

## 三、标题

- 指南页优先用问题式或任务式标题：`## 它解决什么问题`、`## 先看一个例子`、`## 它是怎么工作的`、`## 什么时候会失败`。
- 命令页用：`## 基本用法`、`## 参数`、`## 结果`、`## 示例`、`## 注意事项`。
- 参考页保留名词式标题：`## 字段`、`## 错误码`、`## 兼容性`。
- 同一页的标题层级不要超过 3 级；`####` 只用于字段分组。
- 标题不写「概述」「说明」「相关内容」这类空词；除非页面确实是索引。

## 四、开场与收尾

- 开场直接回答「这是什么 / 解决什么问题」，不铺垫行业背景。
- 第一篇概念页可以给一个最小示例；命令页先给最小命令，再讲参数。
- 收尾用「接下来」「相关页面」「注意事项」指向下一步，不写「总之」「希望本文对你有帮助」。

## 五、示例与代码

- 代码块前用一句话说明它要做什么、放在哪、什么时候触发，代码块后解释结果或关键行。
- 命令、路径、字段名、API 名一律用行内代码。
- 不修改现有代码块中的命令、参数、路径、输出；除非代码本身已过时，否则原样保留。
- 注释只解释不直观的地方；不写「// 设置变量」这类复述。
- 示例之后不要重复粘贴同一段输出；用一句话概括。

## 六、提示框

- `<NoticeBox type="tip">`：经验、推荐做法、能省一步的技巧。
- `<NoticeBox type="info">`：背景、版本差异、概念补充。
- `<NoticeBox type="warning">`：限制、风险、会导致失败的操作。
- 每 300–500 字最多一个提示框；提示框里也只用短句。
- 不为每节都加提示框；没有额外信息就不加。

## 七、表格与列表

- 可枚举的字段、平台能力、错误码用表格；表格前一句话说明怎么读。
- 步骤用有序列表；并列条件用无序列表；不要用列表代替完整句子。
- 列表项尽量同一语法结构；一项只放一个条件或动作。
- 不把表格内容再改写成散文，反之亦然。

## 八、链接与术语

- 第一次出现相关概念时给站内链接；后文不重复堆链接。
- 术语首次出现写中文，括号补英文或缩写；后文统一用一种写法。
- 平台名、产品名、API 名保持项目现有写法，不自行翻译。
- 引号用中文引号「“”」；代码、命令、字段名用反引号，不用引号包裹。

## 九、页面类型差异

- 概念/指南：可以有小故事、反例、设计动机；重点是“为什么”和“怎么理解”。
- 命令/使用页：重点是“怎么用”和“会得到什么”；少讲实现。
- 开发/安装页：重点是步骤、配置、边界；不写教程式铺垫。
- 参考/API 页：重点是准确、可查；不强行口语化。
- FAQ：第一句直接回答，第二段再解释；不绕弯。
- 索引页：只指路，不展开细节。

## 十、事实红线

改写只改变表达和组织，不改变事实。以下内容必须逐字保留或保持语义完全一致：

- 所有命令、参数、路径、URL、版本号、数字、单位、默认值。
- `<CommandUsage />`、`<ChatExample />`、`<ModuleConfig />`、`<ModuleData />`、`<ModuleMeta />` 等组件的属性与内容。
- front matter（`title`、`order`、`submenu`、`description`）与图片引用。
- 表格中的数据、代码块中的代码与输出。
- 已有截图、图注、示例对话。

不能从代码或现有文档核实的新行为，不写。需要补“为什么”时，只解释现有行为，不发明新功能。

## 十一、去 AI 味检查

交付前逐页扫一遍：

- 有没有「旨在」「赋能」「助力」「显著」「一站式」「闭环」「全方位」？
- 有没有连续三个「首先/其次/最后」？
- 有没有每段都用「值得注意的是」开头？
- 有没有把一句话拆成三段、但信息量没增加？
- 有没有为了显得亲切而加「别急」「没关系」「相信我」？
- 有没有标题是「概述」「说明」但内容并不概述？

命中就改；改完读一遍，确认技术事实没有变。
