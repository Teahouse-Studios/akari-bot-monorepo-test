## S2 句子

卡住⇒找主语+动作·按「谁做什么、结果是什么」重写再拆句·禁仅换同义词
禁说明式冒号(叙述句/注释/docstring)·禁冒号当万能连接词·禁机械换逗号·按语境改完整句:原因⇒因为…/避免…/拆句·列举⇒包括…/其中…/涵盖…·条件对象⇒…时/…下/…的…·目的⇒确保…/以…

仅描述当前状态·禁演进史与对照(原本是X现在改为Y|改为Z后|不再逐项W|曾把A直接B|现均为C)·直述当下事实·约束·执行逻辑

## S3 禁否定式防御说明
仅写实际存在的行为与约束·禁解释「不做什么」(适配器不直接调用 Server 内部函数、也不自己写配置文件|CLI 不依赖 core|不会创建文件)

## S9 注释·docstring
解释为什么·不复述代码已写明的动作
单条≤120字符·连续行注释≤3行·写不下⇒抽取为独立函数或说明移到文档页
书面语·禁 跑一下/挂住/淹掉/扫掉/干掉/一堆
禁我们/你·直陈对象/条件/结果(例:此处检查实例目录是否可写)

非公开模块/类/函数不加 docstring·公开接口 docstring 仅写用途/参数/返回值
禁装饰性分隔线与分组注释(`# ====== 配置 ======`)·分组靠文件与函数结构
完整中文陈述句行注释末尾须有中文句号(。)·禁以汉字或英文单词悬空截断
`@func_case` docstring 与描述同样禁「模块/类: 测试内容」冒号句:`core.loader: 模块加载器测试`⇒`core.loader 模块加载器测试`·`akaribot.modules.ai: Anthropic 端点发送对象形式的 tool_choice`⇒末尾加「测试」

## S10 版本·数量·路径·配置·链接·依赖
禁正文写死版本号/包数/页面数/模块数(值来自包清单/`pyproject.toml`/主题清单/当前仓库)

范围⇒当前仓库中的模块/每个内置模块/相关页面·禁「有多少个模块」「有多少个页面」

写配置说明先交代默认值来自哪个文件·再写用户层如何覆盖·禁把手写默认值写成唯一来源·路径/文件名/表名以当前代码与配置为准·禁把旧目录/旧文件名写进操作步骤
API 名称禁手写链接(生成器构建时按导出清单自动加)·仅链接导出清单中有独立条目的名字·方法名按当前类上下文匹配·跨类写完整名(`Bot.post_message`)·代码块与已有链接不处理·别名/属性/无独立条目的名字保持纯文本
只提供密钥表的模块 用 `<ModuleConfig table="<名>_secret" file="config/<名>.toml" />`·禁填不存在的表名
TOML 配置中的表称「配置表」·数据库表与模块持久化的表称「数据表」·禁混用
